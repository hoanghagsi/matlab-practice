D2  "PIN RIPPLE RMS" MEASURES THE WRONG ARRAY  (MEDIUM)
================================================================================
pinRippleRms() (line 2256) is evaluated on S.dose.diff_pct, i.e. on
(local + nl - rashi).  That quantity contains almost no pin ripple by
construction:
  - local and rashi share an IDENTICAL fluence (identity P1), so their
    difference is the smooth material term;
  - nl is the cell-averaged model, piecewise constant per 3 mm cell.
The genuine pin ripple - the intra-cell level/position correlation - lives in
the EXACT 2DRM difference, the only array built from position-labelled fluence.

Measured (agentC2_fix.m F1, default geometry, both grids):

  grid            displayed(diff_pct)   exact-RaShi   local-RaShi
  1.0 mm pixel         0.466 %            0.941 %       0.107 %
  0.5 mm pixel         0.054 %            0.931 %       0.054 %

This is the proof: the REAL ripple is grid-independent (0.941 -> 0.931 %), as a
physical quantity must be, while the number the info box prints collapses by 9x
when the grid is refined.  What pinRippleRms currently reports is therefore a
DISCRETISATION ARTEFACT - the mismatch between cellsToPixels' piecewise-constant
3 mm steps and blockMean3's block alignment - not the pin ripple.  Agent B's
0.466 % is reproduced exactly, so the arithmetic is right; the input is wrong.

Caveat: neither 0.941 % nor 0.931 % reproduces the ~1.35 % quoted elsewhere in
the project.  Those earlier figures come from the Python model at its own
settings and metric mask; I did not reconcile the remaining difference, so
treat ~0.93 % as "what this tool measures on this geometry", not as a
confirmation of the project number.

Proposed fix (NOT applied):
  evaluate pinRippleRms on (exact_Gy - rashi_Gy) when a CURRENT exact_Gy exists
  (see D1), and print "-" otherwise rather than a number derived from diff_pct;
  or relabel the field "ripple of the displayed difference".

================================================================================
T40 - MEASUREMENT AND THE BOUND I SET
================================================================================
Measured (agentC2_fix.m F2, default geometry A=60/B=40, coarse 1 mm grid),
max |(local + nl) - exact| / max(rashi):

  planned field                  2.496 %   <- the overall maximum sits here
  expansion rings (pins exist)   0.991 %   approximation A1, NOT level 0
  beyond the pinned area         0.021 %   <- the level-0 edge term
  over R > 50 % of max           2.496 %   (rms 0.829 %)

Agent B's characterisation is VINDICATED: the level-0 term contributes
essentially nothing to the peak (0.021 %).  An intermediate split I ran first
(agentC2_gaps.m G2) reported 0.991 % "outside the field" and I initially read
that as the level-0 term; it is not.  "Outside the planned field" still contains
pins, because the pinned area extends 3 expansion rings (to +-24 mm) beyond the
+-15 mm field.  Level 0 exists only BEYOND the pins.  F2 corrects G2.

BOUND SET: 3.5 % for the default geometry at the coarse grid.
Reasoning: 1.4x the measured 2.496 %.  The residual is dominated by the physical
pin ripple (~0.93 % rms) plus the A1 breakdown near the field edge, neither of
which the model claims to capture.  1.4x leaves room for grid and rounding
variation while staying tight enough that a sign error or a wrong baseline
(e.g. applying the model to rashi instead of local) would blow straight past it.
Agent B's suggested 3.7 % is equally defensible; I chose slightly tighter.

LIMIT: this bound was measured at ONE geometry and ONE grid.  At Region B =
10 mm the difference map already spans -4.74..+30.40 %, and I did not measure
the residual there.  The bound must be re-measured before it is applied to any
other geometry.
